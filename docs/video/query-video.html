Error 1
AccessDeniedException: … not authorized to perform: glue:GetDatabase on resource: …:database/test_raw
Why: the raw zone is audit only.
✓ Fix: query test_curated instead, or ask for audit access if you really need raw.
Error 2
AccessDeniedException: … not authorized to perform: athena:StartQueryExecution on resource: …:workgroup/primary
Why: the wrong workgroup is selected (here the default "primary").
✓ Fix: pick mtsai-datalake-test-analytics in the workgroup menu (or --work-group in the CLI).
Error 3
Query cancelled: Bytes scanned limit was exceeded
Why: the query read more than your team's per-query limit (5 GB).
✓ Fix: add a WHERE event_date … filter, pick fewer columns, and never run a bare SELECT *.
Error 4
TABLE_NOT_FOUND: Table 'awsdatacatalog.test_raw.trip_events_curated' does not exist
Why: usually the wrong database is selected. A missing Glue permission can also look like this.
✓ Fix: choose test_curated, or write the full name test_curated.trip_events_curated.
List every version of the table
each nightly load adds a new snapshot (version)
SELECT committed_at, snapshot_id, operation FROM "trip_events_curated$snapshots" ORDER BY committed_at DESC;
Time travel: see the table as it was
reproduce exactly what a report saw on a given day (until VACUUM removes old versions)
SELECT count(*) FROM trip_events_curated FOR TIMESTAMP AS OF TIMESTAMP '2026-07-08 00:00:00 UTC' WHERE event_date = DATE '2026-07-07';

You need three things

terraform/modules/athena-workgroup
1. Permission to assume your team's IAM role
2. Your team's workgroup name
3. The database you're allowed to read
Everyone can read test_curated. Only the audit team can read test_raw.
Don't have access yet? Ask the data platform owner to let you assume your team's role. (Who can assume each role is still being narrowed down in the Terraform.)

Two ways in, same role

Both options end in the same place: you're acting as your team's role, inside your team's workgroup.
• The console is easiest for exploring and one-off questions.
• The command line is better for scripts and repeatable jobs.
The region is always ap-south-1 (Mumbai).

The example query

Trips and average fare per city for one day, from the curated table.
The 4 rules keep queries fast, cheap, and under your limit.
Why rule 2 works: Iceberg keeps track of which days are in which files, so a date filter lets Athena skip the other files completely.

Same thing from the command line

aws athena start-query-execution \ --profile datalake-analytics \ --work-group mtsai-datalake-test-analytics \ --query-execution-context \ Database=test_curated \ --query-string "SELECT city_code, …" # → returns a QueryExecutionId aws athena get-query-execution \ --query-execution-id <id> # Status + Statistics.DataScannedInBytes aws athena get-query-results \ --query-execution-id <id>
No output location needed: the workgroup sets it for you.

Stay cheap

You pay for data scanned, not rows returned or time taken.
• Date filters and fewer columns cut the cost the most.
• The per-query limit caps the worst case.
• The monthly budget emails the team at 100%.
Check Data scanned after every new query to learn what's expensive.

Read the error, then check

1. Workgroup: is it your team's?
2. Database: test_curated?
3. Zone: are you allowed to read it?
4. Filter: is there a date filter?
Still stuck? Share the full error text and the query ID with the data platform owner.

Iceberg extras

Because the lake uses Iceberg, every load is a version you can list and query.
Old versions are removed by the weekly VACUUM, so time travel only reaches back as far as the versions that are still kept.
