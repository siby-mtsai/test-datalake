Three layers

Infrastructure: Terraform describes every AWS resource. GitHub Actions applies it.
Application: the Go code is packed into one Docker image. ECS runs it on a schedule.
Data: flows from Postgres through the Go job into S3, where Athena and Glue turn it into tables.
Terraform creates the ECR repo, ECS cluster, task definitions and schedules that run the Go image. That's where the two layers meet.

Modules are building blocks

terraform/envs/test/main.tf
module "lake_bucket" { … } module "glue_catalog" { … } module "export_task" { bucket_arn = module.lake_bucket.bucket_arn kms_key_arn = module.lake_bucket.kms_key_arn raw_database_name = module.glue_catalog.raw_database_name postgres_secret_arn = module.mtsai_api_sim.secret_arn }
Each module's outputs feed the next one's inputs, so the bucket, key, databases and secret are shared, not copied.

No stored AWS keys

.github/workflows/deploy.yaml
GitHub gets a short-lived OIDC token, and AWS swaps it for temporary credentials of role test-datalake. No access keys are stored in GitHub.
The state file records what Terraform built. The DynamoDB lock stops two deploys running at once.

One image, five jobs

export/cmd · export/internal · export/Dockerfile
cmd/ holds the five programs. internal/ holds the shared building blocks they use.
The image is built for ARM64 (cheaper Fargate) on a distroless base: no shell, only the binaries.
Each ECS task definition runs the same image and just picks a different binary.
