lake.CommitToIceberg()internal/lake/iceberg.go — four Athena statements

Each statement goes through AthenaRunner.Run (internal/lake/athena.go): StartQueryExecution in the pipeline workgroup with database test_raw, then polls GetQueryExecution every 1 s until SUCCEEDED/FAILED. Athena writes each query's result file to athena-results/export/.

5a
CREATE EXTERNAL TABLE trip_events_staging_<runID> (…) STORED AS PARQUET LOCATION 's3://…/raw/_staging/trip_events/<runID>/'

Glue a temporary Hive table entry pointing at the step-4 file, so Athena can SELECT from it. No data is copied.

5b
DELETE FROM trip_events WHERE event_date = DATE 'D' -- idempotency: a re-run replaces, never duplicates

Athena if D already had rows, it writes delete files + a new snapshot. On a first run there's nothing to delete.

5c
INSERT INTO trip_events SELECT * FROM trip_events_staging_<runID>

Athena reads the staging Parquet and writes new Parquet data files into raw/trip_events/data/, then the Iceberg manifests + manifest list + new metadata.json into raw/trip_events/metadata/. Glue the table's metadata_location pointer is switched to the new metadata.json in one atomic step. This switch is the commit.

5d
DROP TABLE IF EXISTS trip_events_staging_<runID> -- deferred, runs even on failure

Glue temporary entry removed. The staging Parquet stays in S3 (no lifecycle rule for it yet).

✖ Any 5a–5c error → failure manifest (success:false) uploaded, job exits non-zero.

Maintenance jobs that touch the same files same Docker image, separate ECS task definitions
11

cmd/compact (Sun 03:00 UTC): VACUUM trip_events, VACUUM trip_events_curated → expires old snapshots and physically deletes data/metadata files no snapshot references anymore. Also publishes S3 size-per-prefix to CloudWatch.
cmd/trim: drops old Postgres daily partitions only when export-manifests/D/trip_events.json exists and says success:true.
cmd/erasure: DELETE … WHERE vehicle_id_hash = ? on both tables, then VACUUM, so older snapshots can't bring the data back.

Who writes what

Go codeOnly the staging data.parquet (step 4) and the manifest JSONs (7, 10). It never writes Iceberg files; it only sends SQL to Athena.
AthenaThe engine. Writes every Iceberg data file, delete file, manifest and metadata.json, plus query results.
GlueThe catalog. Holds each table's name → current metadata.json pointer.
IcebergNot a service, a format: the rules Athena follows for data/ + metadata/ and snapshots.

Key ideas

  • Parquet files are immutable. DELETE and INSERT add new files plus a new snapshot. Nothing is edited in place.
  • A commit = Glue's pointer moving to a new metadata.json. Until 5c's pointer swap, readers still see the old table.
  • Idempotent by date: DELETE for D, then INSERT for D. Re-running a date replaces its rows instead of duplicating them.
  • Every hop is checked: Postgres ↔ raw (step 6) and raw ↔ curated (step 10), both by row count + SUM(trip_id).
  • Never touch data/ or metadata/ by hand. Always change the table through SQL in Athena.
